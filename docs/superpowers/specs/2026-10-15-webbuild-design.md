# H5000M 中文在线定制编译器实施规格

日期：2026-10-15。目标仓库：xxx00000/OpenWRT-CI-H5000M。
已检查 main 提交：88bbb87822799302e7a5cbe71ad98689b6f2b0aa。实施前重新检查，避免覆盖并行修改。

## 目标与边界

在现有 ImmortalWrt 编译项目上增加可操作中文网页、安全后端和 Actions 集成。保留现有插件、模组管理、驱动、源码版本与固定提交，以及原有镜像安全检查。网页不是模拟编译器；未部署后端时明确显示未连接，不能伪造构建状态。

原有插件默认全部保留。用户可添加经管理员批准的软件包，或移除本次额外添加的软件包；本期不允许删除现有插件、驱动和它们的必要依赖。包名语法和白名单同时验证，构建时核对实际包元数据与 defconfig 结果，不允许输入 shell、任意仓库地址或构建命令。

## 交付架构

采用容器化 Node.js 服务，同源提供响应式网页和 API；用 HTTPS 反向代理部署到用户服务器。提供 Docker Compose、环境变量示例和中文部署说明。无需额外数据库服务；任务元数据持久化到数据卷，秘密使用服务端密钥加密并设置有效期。单实例运行。

GitHub App 安装范围限定目标仓库，权限为 Actions 读写、Contents 读取；不授予内容写入权限。App 私钥、客户端凭据及加密密钥仅存服务端。网页通过 GitHub 登录；后端检查登录用户对固定目标仓库是否有 push/admin 权限，再允许发起或查看私人任务。会话使用 HttpOnly、Secure、SameSite Cookie，写操作验证 Origin 和 CSRF token，限制请求大小与频率。

另一种部署方式是 GitHub Pages 加独立 API，但增加跨域和会话部署复杂性，本期以同源服务作为完整交付方案。

## 网页配置

提供基本信息、网络、无线、插件主题和构建记录区。支持移动端，中文错误提示，加载和失败状态。

- 编译者、固件版本备注：限制长度和控制字符；写入独立固件元数据文件，避免改变已固定的上游版本标识。
- LAN：默认 10.0.0.1/24，验证 IPv4、可用主机地址、前缀和 DHCP 地址池。界面显示管理地址及网络变更提醒。
- root 密码：示例 password，通过明确输入设置；不写进模板、URL、公开仓库或预览。服务端生成 SHA-512 crypt 哈希，构建侧仅接收哈希。
- 无线：默认 2.4GHz A3KM、5GHz A3KM+；分别设置启用状态，WPA2-PSK，密码按 UTF-8/PSK 规则验证。Wi-Fi 密码示例 password，要求用户明确提交，不暗中使用示例。
- 主机名：合法 DNS 主机标签；时区使用受控选项，默认 Asia/Shanghai 与对应 POSIX 时区。
- 主题：从确认可用的主题白名单选择；切换默认 LuCI 主题但保留 Argon 及现有配置插件。
- 插件：展示保留基线、保护状态和额外包；仅额外包可删除。

模板保存于浏览器本地，可导入导出 JSON；格式有 schemaVersion，不包含 root/Wi-Fi 密码、令牌或构建领取凭据。导入、网页、API、构建端各自验证。预览始终脱敏，错误返回不回显秘密。

## 编译衔接与秘密保护

在目标仓库新分支实施，以 PR 交付；不直接覆盖 main。原 workflow_dispatch 无自定义任务输入时仍保持原编译路径。新增定制任务输入只接受 UUID，不传密码或配置 JSON。

后端先持久化任务，再对固定仓库、固定 workflow 和允许的 ref 调用 workflow_dispatch。用任务 UUID 写入 run-name 关联运行，不能将其他用户的最新构建误认为当前任务。触发失败保留可重试状态，避免重复提交；后端仅轮询自己的任务并展示 GitHub 状态、日志页面和下载入口。

定制构建用 GitHub Actions OIDC 身份向后端领取配置。后端验证签名、issuer、audience、有效期、目标仓库 ID、ref、workflow 身份、run ID 与任务关联，阻止跨仓库和伪造任务领取。仅可信定制 job 设置 id-token: write；其余权限保持最小。

密码不写入 Actions inputs、环境持久文件、命令参数、GitHub output 或公开 artifacts。生成器使用参数数组及文件 API，不 eval，不把用户值插入 shell 源码。构建仅将必要配置写入权限受限的工作文件，禁止输出其内容。Wi-Fi 密码最终必然存在于固件中，因此含私人配置的固件不得公开上传。

定制镜像及可能含秘密的编译日志不使用公开 artifact 上传步骤。镜像通过 OIDC 认证上传至后端私有存储；只有任务所属且仍有仓库权限的用户可下载。后端默认保留结果 7 天，秘密配置在构建完成后清理，失败任务配置最多保留 24 小时。上传采用流式处理及大小限制，下载校验任务权限与路径。

公开 Actions 日志仍需避免秘密输出：生成文件不打印，编译日志转入受限文件；页面说明自定义第三方包可能泄漏输入，白名单只接受已审核包。公开默认构建与私人定制构建的日志和上传策略分开处理。

## 首次启动与原功能保护

复用现有 /etc/uci-defaults 和 h5000m-firstboot，避免新增脚本与硬编码 A5kM 设置互相覆盖。密码哈希写入 shadow；LAN、主机名、时区和主题通过 UCI 设置。仅在全新配置上应用，恢复旧配置的行为写入部署与刷机说明。

保留当前 AU、EHT20/EHT160、模组所有权管理等已有参数。无线按设备 band 识别 2g/5g，不假定 radio0/radio1；对于缺少 band 的设备，结合现有 hwmode、驱动/设备能力识别，不能确定时保留配置并报告重试失败，禁止猜测。只更新 LAN AP，不覆盖客户端、访客或模组接口；不存在 LAN AP 时为已识别设备创建。启用/禁用均处理 wifi-device 和相应 AP，并在配置完成后设置成功标记。

## 验证与验收

自动检查覆盖配置边界、CIDR/DHCP、SSID 字节长度、密码规则、主题/包白名单、命令注入、模板脱敏、会话与 CSRF、越权访问、OIDC 伪造与重放、触发失败和运行关联、私有下载权限。

回归检查现有测试、插件/驱动基线和定制 defconfig；验证生成脚本语法及模拟 UCI 在设备顺序变化、缺失频段、已存在接口和禁用无线时的行为。检查敏感值不出现在可公开的配置、预览、日志与打包文件中。

在浏览器实测桌面与手机尺寸、模板导入导出、校验、后端未配置错误和构建状态流程。后端测试使用模拟 GitHub/OIDC，真实联调需完成 GitHub App、HTTPS 和服务器部署后进行。

最终交付源码/PR、容器部署方法、GitHub App 设置步骤和所需 secrets 清单。区分本地测试通过、真实 Actions 编译通过和硬件首次启动验证；没有真实证据不宣称固件可刷或部署已上线。完整编译可能需要数小时，硬件验证需要用户设备。

## 部署前提

需要可运行 Docker 的服务器、HTTPS 域名、GitHub App 安装及服务端配置。当前尚未提供这些资源，不会宣称已经有公网可用地址。代码交付包含本地可运行入口和上线步骤；如用户提供部署资源，则继续部署并完成真实编译联调。
